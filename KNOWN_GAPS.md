# Known gaps

What this project has *not* done, stated plainly. The block at the bottom is regenerated by
`scripts/run_all.py` after every run; the notes here are written by hand.

## Environment constraints hit while building this

1. **No GPU on the build machine.** CodeBERT fine-tuning costs roughly 6 s/step on this 8-core laptop
   CPU, so the real-data run uses the `local_real` preset: 1,000 training rows, `max_len` 128, one
   epoch, one seed for the transformers. The `lite` preset (20k rows, `max_len` 256, 2 epochs) is the
   intended portfolio run and is unchanged in `configs/lite.yaml` — it needs a GPU session.

2. **The Kaggle CLI rejects write operations from this machine.** Read endpoints work
   (`kaggle datasets files`, `kaggle datasets list --mine`), but `kaggle datasets create` and
   `kaggle kernels push` return *"Authentication required"*: the installed CLI wants the newer
   access-token, not the legacy `kaggle.json` key that is configured here. The fix is one interactive
   command the repo owner has to run:

   ```bash
   kaggle auth login                      # OAuth in the browser
   # or: generate a token at https://www.kaggle.com/settings/api and save it to ~/.kaggle/access_token
   python scripts/kaggle_drive.py --preset smoke --repo-url https://github.com/ranjankndev/codedetection-human-machine.git
   python scripts/kaggle_drive.py --preset lite  --repo-url https://github.com/ranjankndev/codedetection-human-machine.git
   ```

   Everything on the Kaggle side is already built and tested up to that call: `kaggle/kaggle_entry.py`
   (script kernel that clones this repo, installs only the missing extras and runs `run_all.py`) and
   `scripts/kaggle_drive.py` (push → poll → download → exit code from `status.json`, with network /
   auth / quota diagnosed separately). The data itself was fetched instead from the Hugging Face mirror
   `daniilor/SemEval-2026-Task13`, which is the same release.

3. **Task C is ignored.** The release ships a task C; this project is scoped to A and B, as the original
   competition entry was.

## Methodological gaps worth naming

- **Single seed for the transformer rows** at `local_real` (three seeds for the cheap models, with the
  spread reported). Seed variance for CodeBERT-sized models on 1k rows is not negligible; the CIs are
  bootstrap CIs over rows, not over seeds, and the report says so.
- **Proxy OOD splits.** Held-out language (A) and held-out generator checkpoints (B) stand in for the
  organisers' hidden test sets, whose labels are not public. The official *validation* parquet is used
  as an extra in-distribution comparison where it carries labels.
- **The stacking row is fitted on in-sample logits** (the base transformer has seen those training rows),
  which biases the stacker towards trusting the logits. The caveat is recorded in its metrics file.
- **LM features are not recomputed for perturbed text** in the stress test; the LM block is zero-padded
  there, so stress numbers for LM-fused variants understate the model slightly.
- **No domain-adversarial (DANN) run and no open-set rejection for Task B.** Both are described in
  `docs/INTERVIEW_NOTES.md` as the next experiments; neither was run.
